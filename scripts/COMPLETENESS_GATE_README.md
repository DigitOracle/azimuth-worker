# Completeness gate (v393)

**Rule (Kendall, 7 Oct 2026):** if it is in a government register (or a building register) it must be findable in the product, with an honest label for what we do and do not know. KORE by Imtiaz and The Archive by Imtiaz were registered and not on the developer page, because that page built cards only from projects with settled sales.

`scripts/check_completeness.py` reads the live store read-only through the public `/img/<name>` route (devmap_index, search_index, plots, plot_positions, community_positions, investor_tiers_index, map_prices, buy_extra, rent_index, and each district's blocks and unit-mix file), tests every register project in `scripts/completeness_universe.csv` against nine surfaces (map footprint, plots layer, search list, developer page, position ladder, building page, Brief, investor facts, unit-mix card; the rules are in `scripts/completeness_core.py`), and **exits 1** when (a) any named fixture is missing from a surface where it must appear (KORE by Imtiaz, The Archive by Imtiaz, Chelsea Residences by DAMAC, Chelsea Residences 2 by DAMAC, Harbour Lights, Coral Reef, Cove Grand Residence by Imtiaz, Upper Crest, Vento Tower under ANAX and not under Beyond), (b) the coverage of any surface for register projects drops below its threshold in `scripts/completeness_gate.json` (measured minus 1 point), or (c) the count of unfindable entities rises above the stored baseline. Every run appends to the audit trail `scripts/completeness_audit_trail.csv`. `--baseline-update` re-measures and rewrites the thresholds and baselines (it never baselines a failing fixture); `--self-test` is the negative control (it corrupts a copy of the live data, drops two fixtures and 15% of the cards, and exits 0 only if the gate fails on it and names the damage). A full live run takes about 2.5 minutes cold (about 15 seconds with `--fast`, which skips the per-district files and therefore S1, S4 and S8); a second run inside 15 minutes reads the local cache.

**Where it must run.** Before every put, on the new file (`--index`, `--plots`, `--plot-positions`, `--community-positions`, `--nosales`), so a regression is stopped before it is published; and once after every put, on the live store.

## v397g - every surface layer, and the hard stop (7 Oct 2026)

**Layers.** The gate now reads every layer the v397 release adds, each optional (absent = skipped and reported as `layer not published`, so it runs both before and after the publish): S1/S3 developer page = index + `img_devmap_nosales` + `img_devmap_notconf` + `img_devmap_announced` (announced projects are in no register: a named fixture may use them, register coverage never counts them); S2 search = plots + `img_search_extra` (+ the district parts its `parts` names) + `img_search_extra_announced`; S4 = building outlines + plot positions + community positions (card keys) + `img_community_positions_p` (`p:<number>`). Live mode reads the live `/img` routes (a 404 is "not published"; the owner key in `C:\Dev\azimuth-listener-naj\.env` is used only if a route answers 401 and is never printed). Local files: `--nosales --notconf --announced --announced-search --search-extra-dir --community-positions-p` (the old `--index --plots --plot-positions --community-positions` still work). `--require-layers` turns a skipped layer fixture into a failure: use it after the publish.

**Fixtures added.** Burj Azizi and Trump Tower (search; need the v397b sx entries), Tamani Arts Offices (notconf), Sobha Sanctuary (announced, found by name; needs the announced and announced-search layers), Elegant Tower (project 100, `p:100` community position). A layer fixture is SKIPPED, not failed, while its layer is not published. KORE and The Archive stay hard fixtures: they fail whenever no nosales layer (live or local) shows them. Fixture lookups now use the first name in `names` as well (the display name was being used instead).

**The hard stop.** `scripts/gate_guard.py` is the one shared helper. It reads live once ("live now"), measures again with the candidate file substituted for its layer, prints the table (threshold, live now, candidate, delta, projects lost, status) and BLOCKS (exit 1, before anything is written) when the candidate makes a fixture that passes live fail, takes a surface under its threshold, or drops a surface by 1 point or more. It is relative to live on purpose: a publish that does not itself fix an existing failure (KORE before the nosales key goes up) is still allowed; `--strict` blocks on any failing fixture or threshold. `--full` also compares the unfindable counts. It works in dry-run mode (same table, "the real publish WOULD BE BLOCKED", the dry run carries on). `--skip-gate` / `-SkipGate` publishes UNGATED with a loud banner on stdout and stderr. A guard that cannot run (live unreadable, file missing) fails closed.

Guarded: `publish_nosales.py` (nosales, search_extra), `publish_notconf.py`, `publish_announced.py` (announced, search_extra_announced), `publish_community_positions.py`, `publish_community_positions_p.py`, `publish_plot_positions.py`, `publish_devmap_attr_v390.ps1` and the older index publishers (v373, v325, v323, v327, evidence, offplan; profile_v321 passes `-SkipGate` through to offplan), `publish_investor_facts.ps1` (investor_tiers_index), `publish_rent_index_12m.ps1` (rent_index), `publish_cov_cards.ps1` (map_prices and buy_extra only: the unit-mix shards it also writes are not a guard layer, and `--fast` does not measure S8). Not guarded, on the exemption list in `test/test_v397g_gate.py` with the reason: `publish_centres2040.py` and `publish_devmap_delivery.ps1` (no gate surface reads those keys). The test fails if a new `publish_*` script is neither wired nor exempt.
